# Texture Studio

Select a 3D object or named part, adjust its letters in an isolated preview,
then apply the result and save a reusable texture. Texture authoring now has
its own **Studio → Textures** module alongside Effects and Atmosphere.

![Texture Studio editing a tree crown with Unicode arrows](https://raw.githubusercontent.com/joaovrmoraes/ascii-engine/v0.1.0/docs/captures/texture-controls-2026-10-14/orca-window.png)

## What's new

- **Objects and parts:** preview a whole object or an existing named part,
  including imported GLTF groups. A tree's crown and trunk can keep different
  appearances. Orbit, pan, zoom, frame the object and pause motion.
- **Letters:** custom alphabets with up to 128 single Unicode characters,
  six starter character sets, installed font families, regular/bold weight
  and letter rotation.
- **Visibility and layout:** letters-only or dark-occluder rendering,
  front/both body faces, world size, spacing and density. Letters-only
  surfaces discard the gaps; glyph bodies hide their solid occluder.
- **Ink and color:** base RGB, strength, gap tint, contrast, tone offset,
  shadow steps, 2–8-stop palettes, scene/uniform local shading and emissive
  color/intensity.
- **Preview lighting:** exposure, background, main light color/intensity/
  direction/shadows, ambient sky/ground, fill light and fog. Save this rig
  with the texture, apply it to the scene explicitly, or save it as an
  Atmosphere asset. Applying a texture preserves scene lighting.
- **Reusable assets:** save, update, copy, reopen and apply textures from
  **Assets → Textures**. Download/import `.texture.json` files. Project
  files, browser drafts, item insertion and exports retain texture assets.
- **History and automation:** local texture undo/redo, one scene undo action
  per application, and `texture.define` / `texture.apply` through the
  authoring API and MCP.

Existing scenes keep their rendering defaults when the new optional settings
are absent. The core engine remains independent of the editor and game rules.

## Try it

Install the source with Node.js and pnpm 11.9.0:

```bash
pnpm install
pnpm dev
```

Open [localhost:1440](http://localhost:1440), select an object and click
**Create texture**, or open **Studio → Textures**. Choose the object/part,
edit the preview, then use **Apply to object** / **Apply to part** and
**Save to Assets**.

The release includes importable examples:

- `blue-hatch.texture.json`: a basic character/layout recipe.
- `emerald-symbols.texture.json`: Unicode arrows, bold font, letters-only
  rendering and a colored preview light rig.
- `texture-studio-demo.ascii.json`: a complete scene with an embedded
  multipart model and saved textures.

Open texture files through **Import or download file → Open texture**.
Open the example scene through **File → Open**.

## Validation and current scope

`pnpm check` passed with **109 tests**, type checks and a production build.
The texture suite passed **71 real WebGL assertions**, and the existing
authoring and API regressions passed. Rendering was checked in Orca Browser
and GPU Chromium, with no runtime or shader errors.

This module supports surface/body mesh appearances and existing named parts.
It does not automatically split arbitrary faces or material slots. Fonts use
installed families/fallbacks and are not embedded; combining character
sequences, raster painting and transparent PNG export are outside this
release. Water, terrain/carpet and effects use their own modules. Emissive
letters brighten themselves without illuminating nearby objects. Native
desktop execution and arbitrary decoder-dependent models remain unverified.
